# MultiSaver configuration and compatibility

Run `multisaver.scr /c` (or double-click it) to create `multisaver.ini`
beside the launcher, append sections for connected monitors, and open it in
Notepad. Keep the launcher in a writable folder. The launcher needs no
administrator rights, installed service, startup entry, .NET, or background
manager. It runs only when Windows starts the screen saver.

Save the INI as **UTF-16 LE with BOM** when using non-ASCII paths. `/c` creates
that encoding automatically. ASCII-only INIs are also supported. UTF-8 with
non-ASCII characters is not supported by the Windows profile APIs used here.

```ini
[Launcher]
DefaultSaver=C:\Windows\System32\Mystify.scr

; Replace these example IDs with the sections generated by /c.
[Monitor:\\?\DISPLAY#EXAMPLE_A#INSTANCE_A#{monitor-interface-guid}]
Saver=savers\First.scr

[Monitor:\\?\DISPLAY#EXAMPLE_B#INSTANCE_B#{monitor-interface-guid}]
Saver=%SystemRoot%\System32\Ribbons.scr

[Monitor:\\?\DISPLAY#EXAMPLE_C#INSTANCE_C#{monitor-interface-guid}]
Saver=none
```

- `DefaultSaver` is used for unconfigured monitors and the Windows preview.
- A missing or empty per-monitor `Saver` inherits `DefaultSaver`.
- `none` explicitly keeps a screen black. An empty default also means black.
- Paths may be absolute, relative to the launcher folder, or contain Windows
  environment variables. Do not append arguments. Keep paths under 260 UTF-16
  code units; long paths are not supported by this launcher.
- Invalid/missing paths, directories, non-`.scr` files, and the launcher itself
  (including hard links) are rejected. A failed child launch leaves that screen
  black. Fullscreen mode does not display blocking error dialogs.
- Settings are read at startup; save edits and restart the screen saver.

## Display identity

Sections use the `GUID_DEVINTERFACE_MONITOR` device interface name obtained via
`EnumDisplayDevicesW(..., EDD_GET_DEVICE_INTERFACE_NAME)`, rather than the order
returned by `EnumDisplayMonitors` or `\\.\DISPLAY1`. Windows normally keeps this
identity across changes in enumeration order. It is **not a guaranteed permanent
physical serial number**: port/dock changes, driver reinstallations, remote or
virtual displays can change it. Rerun `/c` and copy the desired assignment to the
new section. Old sections remain for disconnected displays. Where the driver
provides no identity, the default is used; there is no ordinal fallback.
The generated `Info` value shows the current GDI display name, size, position,
and primary status to help identify each section; it is informational only.
Use extended desktop mode; mirrored outputs cannot show separate content.
The wrapper hosts at most 32 desktop monitors.

## Native screen saver entry points

| Invocation | Behavior |
| --- | --- |
| `/s` or `/S` | One borderless host per monitor, each child receives `/p HWND` |
| `/p HWND` or `/p:HWND` | Forward preview to `DefaultSaver`; no fullscreen hosts/input hooks |
| `/c`, `/c:HWND`, `/c HWND`, no arguments | Edit launcher INI; parent parameter is accepted but the editor is independent |

Configure an individual child by running `ThatSaver.scr /c` separately. The
wrapper's Configure button edits monitor assignments. It does not invoke every
child configuration dialog. A missing/invalid preview parent or default returns
exit code 2. Valid preview waits for the child or the parent window to disappear.

## Compatibility limits

Only children that implement the standard **`/p HWND` embedded preview protocol**
are supported. Each instance must draw inside its supplied window at arbitrary
sizes, permit multiple simultaneous processes, and accept the full decimal HWND
value. Software that ignores preview mode, forces fullscreen, requires a global
singleton, or opens its own dialogs is unsuitable. The launcher does not inject
code, reparent arbitrary fullscreen windows, or fall back to `/s`.

Native 32-bit child processes can run under a 64-bit launcher on Windows 11,
subject to the child's HWND parsing and preview implementation. Test each saver
individually; the examples above are path examples, **not a compatibility claim**
for those Windows savers. Preview rendering can differ from the child's `/s`
rendering, including reduced animation and different settings.

Fullscreen keyboard press, mouse click/wheel, or mouse movement beyond 6 pixels
after a 750 ms startup grace period dismisses all children together. Display
topology changes also dismiss the session. Input hooks exist only during `/s`.
Both hooks must install successfully or the session cleans up and exits.
A kill-on-close Windows Job Object owns the children (including descendants), so
launcher shutdown also stops them. Incompatible children may exit on their own,
leaving a black host until user input. Children that actively resist preview
embedding or intercept input still require manual compatibility testing.

Use only trusted `.scr` files: they are executables. This wrapper does not
implement a password dialog or workstation lock. Let Windows enforce sign-in
on resume in Screen Saver Settings; that policy requires a manual system test.

## Portable use

Build or unpack the portable ZIP into a writable folder, then configure `/c`.
To select it in Windows Screen Saver Settings, use the `.scr` context menu's
Install option or Windows' standard screen saver selection. This fork does not
write system directories or automatically alter the active screen saver.
Removing the folder removes the launcher; first select another screen saver
if Windows currently points at it.

The historical `engine/` binary stays in Git history/source for provenance,
but is neither required nor included in this fork's portable package. Its
redistribution terms are not established by the wrapper's MIT license.
